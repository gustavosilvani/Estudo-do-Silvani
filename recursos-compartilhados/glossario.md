# 📖 Glossário de Termos Técnicos

Glossário de termos técnicos usados nas trilhas da escola.

## A

**Abstração**  
O processo de esconder detalhes de implementação e mostrar apenas funcionalidades essenciais.

**Aggregate (Agregado)**  
Um cluster de objetos de domínio que são tratados como uma unidade única para propósito de mudanças de dados.

**Anti-pattern (Anti-padrão)**  
Uma solução comum a um problema recorrente que é ineficaz e pode ser contraproducente.

**Arquitetura**  
A estrutura fundamental de um sistema de software, definindo como os componentes se relacionam.

## B

**Bounded Context**  
Uma fronteira explícita dentro da qual um modelo de domínio particular se aplica.

## C

**Coesão**  
A medida de quão relacionadas e focadas são as responsabilidades de um módulo ou classe.

**Coupling (Acoplamento)**  
A medida de interdependência entre módulos de software.

## D

**Domain Model (Modelo de Domínio)**  
Uma representação abstrata do conhecimento e atividades que governam um domínio de aplicação.

**Domain Service (Serviço de Domínio)**  
Uma operação que não pertence naturalmente a uma entidade ou value object.

**DRY (Don't Repeat Yourself)**  
Princípio que visa reduzir repetição de código.

## E

**Entity (Entidade)**  
Um objeto que possui identidade única e é distinguido por sua identidade, não por seus atributos.

**Encapsulation (Encapsulamento)**  
O princípio de esconder detalhes internos e expor apenas o que é necessário.

## I

**Interface**  
Um contrato que define quais métodos uma classe deve implementar.

**Inversion of Control (IoC)**  
Um padrão onde o controle de fluxo do programa é invertido, geralmente através de injeção de dependência.

## L

**Liskov Substitution Principle (LSP)**  
Princípio que afirma que objetos de uma superclasse devem ser substituíveis por objetos de suas subclasses.

## O

**Open/Closed Principle (OCP)**  
Princípio que afirma que entidades de software devem estar abertas para extensão, mas fechadas para modificação.

## P

**Polymorphism (Polimorfismo)**  
A capacidade de objetos de diferentes tipos responderem ao mesmo método de formas diferentes.

**Pattern (Padrão)**  
Uma solução reutilizável para um problema comum em design de software.

## R

**Refactoring (Refatoração)**  
O processo de reestruturar código existente sem alterar seu comportamento externo.

**Repository (Repositório)**  
Um padrão que abstrai a lógica de acesso a dados, fornecendo uma interface mais orientada a objetos.

**Responsibility (Responsabilidade)**  
Uma razão para mudança em uma classe ou módulo.

## S

**Single Responsibility Principle (SRP)**  
Princípio que afirma que uma classe deve ter apenas uma razão para mudar.

**SOLID**  
Acrônimo para cinco princípios de design orientado a objetos:
- Single Responsibility Principle
- Open/Closed Principle
- Liskov Substitution Principle
- Interface Segregation Principle
- Dependency Inversion Principle

## V

**Value Object (Objeto de Valor)**  
Um objeto que é definido apenas por seus atributos e não possui identidade única.

## Y

**YAGNI (You Aren't Gonna Need It)**  
Princípio que sugere não adicionar funcionalidade até que seja realmente necessária.
